# DeepSeek DSpark optimization — 2026-11-01

The original serving profile, NVIDIA stacks, kernel, Multikernel and old Qwen backend remain unchanged. Private experiments serially unload/pause the shared API, run one bounded engine at a time (42G max, 38G high, swap 0), then restore the API automatically. No reduced expert count: all six experts remain enabled. No lossy disk expert skipping.

## Repeatability and controlled comparison

Identical raw protocol GEN requests bypass HTTP and explicitly use temperature=0, top_p=1, top_k=1, seed=42. Adaptive expert migration produced differing repeated code tokens; disabling adaptive migration with --no-expert-cache made both short prompts repeat exactly. This flag freezes residency; it retains initial GPU-resident experts and does not imply CPU-only operation. CPU/GPU placement changes arithmetic, so the original no-drafter and drafter-loaded runs cannot establish exact equivalence across different residency. This observation does not establish that the model or drafter is intrinsically incorrect.

Controlled drafting tests load DSpark in BOTH arms of the SAME process and freeze residency, then compare spec=0 with spec=1 token by token. Prefix reuse, persistent slots, auto pinning and disk skipping are disabled. Target-only and drafting outputs match on the recorded short greedy tests. This is validation on those prompts/configurations, not a general correctness proof; sampled generation and long contexts remain unqualified.

DSpark's residency competes with target weights: no-drafter initial allocation has more target experts on GPU. Controlled same-residency speedups therefore are NOT end-to-end speedups over the original adaptive no-drafter API. Token rates below use generated token count / engine-reported decode duration, excluding prompt/load work. Native CLI's displayed rate uses a different token-count convention; avoid mixing the two.

## Dominant cost and rejected tuning

Native CLI 64-token code reference with fixed residency and 8 CPU threads: 4.59 tok/s (CLI convention), about 395 MB expert reads/token, 149 ms storage wait/token, 76.8% RAM-store hit rate. Built-in CPU lane, head wait and layer timers overlap: do not sum them as exclusive wall-time. Engram reads were about 0.12 ms/token. This is primarily expert I/O pressure, not evidence that CUDA launch or output projection dominates.

12 CPU threads: 4.37 tok/s; 4 threads: 4.29. All 64 target IDs identical. Retain 8 threads.
Cache sweep: LRU32GB 4.61 tok/s; LFU32GB 4.51; LFULRU32GB 4.03; LRU36GB 4.59. All 64 IDs identical; all exits successful, zero failed expert reads. Larger cache reduced reads slightly without a speed benefit, so retain LRU32GB. Peak sweep memory 34.7G, zero scope swap.
